<objective>
Scaffold the committed Android shell and prove the whole phase on a device: `capacitor.config.ts` with the day-one irreversible origin pin, the generated `android/` Gradle project committed wholesale, a first debug APK build, and the on-device boot acceptance with the PLAT-02/PLAT-03/PLAT-04 runtime probes.

Purpose: PLAT-01 is the phase's headline truth (the web editor runs unchanged in the shell on a real device), and the origin pin plus manifest hardening are cheap now and expensive later — the scheme binds IndexedDB at first launch, and the applicationId becomes the device identity. This plan also executes the environment gates research flagged (A1 placeholder rewrite, A2/A3 JDK/SDK) instead of assuming them.

Output: committed `android/` project + pinned `capacitor.config.ts` + pin test + a booted, probe-verified debug APK + the consolidated VAL-02 web-gate re-run.

Sizing note (checker Issue 2): held as one plan deliberately. The projected ~75k tokens sit inside the plan budget and the weight is wall-time waits (Gradle distribution download, on-device interaction), not implementation context — Task 1 and Task 4 are human gates consuming little context, and Task 2's bulk is CLI-generated content committed wholesale. Splitting scaffold from build/device would separate the Gradle build from the local state it consumes (android/local.properties, the Task-2 JDK verdict, the APK path) without reducing the wait time, and would put the boot-acceptance human-check in a plan that never saw the build.
</objective>
