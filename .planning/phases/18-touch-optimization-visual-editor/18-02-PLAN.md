**Add pinch state.** Add a ref `activePointersRef = useRef<Map<number, {x:number;y:number}>>(new Map())` and a ref `pinchPrevDistanceRef = useRef<number|null>(null)`. Using refs (not state) avoids re-render churn during gesture move.

**Extend handleCanvasPointerDown (the handler from Task 1):** at the top (before the existing clear-selection logic), record the pointer: `activePointersRef.current.set(e.pointerId, { x: e.clientX, y: e.clientY });` and `(e.currentTarget as HTMLElement).setPointerCapture(e.pointerId);`. If after insertion `activePointersRef.current.size === 2`, initialize `pinchPrevDistanceRef.current` to the distance between the two stored points and return early (skip the clear-selection/connect-cancel behavior so the pinch gesture does not blow away canvas state). If size === 1, fall through to the existing single-pointer logic from Task 1.

**Add handleCanvasPointerMove(e: React.PointerEvent):** if `!activePointersRef.current.has(e.pointerId)` return. Update the stored coords for this pointerId. If `activePointersRef.current.size === 2` and `pinchPrevDistanceRef.current != null`: compute current distance between the two pointers, derive `zoomDelta = currentDistance / pinchPrevDistanceRef.current`, set `setZoom(z => Math.max(0.25, Math.min(3, z * zoomDelta)))` (use the EXISTING 0.25..3 clamp from lines 292/299), update `pinchPrevDistanceRef.current = currentDistance`, and call `e.preventDefault()` ONLY while the two-pointer pinch is active (per Pitfall 2 — do not preventDefault for single-pointer moves).

**Add handleCanvasPointerUp(e: React.PointerEvent) / handleCanvasPointerCancel:** release capture `(e.currentTarget as HTMLElement).releasePointerCapture(e.pointerId)` (guard if not captured), delete the pointerId from activePointersRef, and when the map drops below 2 pointers reset `pinchPrevDistanceRef.current = null`. When the map becomes empty, also restore any single-pointer intent state if needed.

**Wire the JSX on the canvas container div (lines 281-287):** add `onPointerMove={handleCanvasPointerMove}`, `onPointerUp={handleCanvasPointerUp}`, `onPointerCancel={handleCanvasPointerCancel}` alongside the Task-1 `onPointerDown`. Assert a single pointerDown+pointerMove does NOT change zoom. Assert releasing one pointer then moving the other does not crash or mis-zoom. Use jest.useFakeTimers only if needed; otherwise real timers are fine. Mock getBoundingClientRect consistently with Task 1's test setup.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→browser-pointer-runtime | Untrusted pointer/touch input crosses from the browser into React PointerEvent handlers; this plan reads e.clientX/Y, e.pointerId, e.pointerType, e.shiftKey — no privileged operations, no DOM mutation beyond setPointerCapture on the target element. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-04 | Tampering | VisualEditorCanvas pointer handlers (pointerId/coords) | low | mitigate | Inputs are read-only pointer properties; setPointerCapture target is e.currentTarget (not attacker-controlled). No user-supplied string parsing. Mitigation = none beyond standard React event handling; accept residual as low. |
| T-18-05 | Denial of Service | activePointersRef Map (unbounded growth) | low | mitigate | Map is keyed by browser-issued pointerId and always deleted on pointer-up/cancel; a malicious client cannot create unbounded entries because the browser issues finite pointerIds per gesture. Mitigation = guaranteed cleanup in pointer-up/cancel handlers. |
| T-18-06 | Elevation of Privilege | Unit/E2E test scaffolds | low | accept | Test-only artifacts; no production runtime path. Acceptable. |
| T-18-07 | Tampering | setPointerCapture / releasePointerCapture calls | low | mitigate | Always paired (down→capture, up/cancel→release) and guarded by "is this pointerId captured" check; no orphaned captures that could hijack later events. Mitigation = the capture-pairing discipline in Task 1/2. |
</threat_model>
